# Data Model: [Working Title] Fantasy Baseball Sim

## Overview

The schema is organized into five areas:

1. **Users, leagues, and teams** — the social and organizational layer
2. **Players and rosters** — MLB player data and fantasy roster assignments
3. **Matchups and lineups** — the weekly competitive structure and lineup selections
4. **Player stats** — pre-lock and post-lock stat snapshots that drive the sim
5. **Sim results** — play-by-play events, box scores, and line scores

All tables live in PostgreSQL via Supabase unless otherwise noted.

## 3. Matchups and Lineups

### matchups
One row per weekly head-to-head matchup. The schedule is generated by the platform at the start of the season.

| Column | Type | Notes |
|---|---|---|
| id | UUID | PK |
| league_id | UUID | FK to leagues.id |
| week_number | integer | |
| home_team_id | UUID | FK to teams.id |
| road_team_id | UUID | FK to teams.id |
| road_sp_deadline | timestamptz | Road team must lock SP by this time |
| home_sp_deadline | timestamptz | Home team must lock SP by this time; later than road deadline |
| batting_order_deadline | timestamptz | Both teams must lock batting order by this time |
| sim_scheduled_at | timestamptz | When the sim is set to run |
| sim_status | sim_status | Default: scheduled |
| created_at | timestamptz | |

Note: lineup lock state is never stored explicitly. It is always derived by comparing the current time to the relevant deadline columns.

---

### lineups
One row per team per matchup. Created with default selections when the matchup is generated. Only saved when valid.

| Column | Type | Notes |
|---|---|---|
| id | UUID | PK |
| matchup_id | UUID | FK to matchups.id |
| team_id | UUID | FK to teams.id |
| sp_player_id | UUID | FK to players.id; the designated starting pitcher |
| updated_at | timestamptz | |

Unique constraint: (matchup_id, team_id)

---

### lineup_batting_order
The 9-slot batting order for a lineup. Each row is one batting position. Only saved when the full lineup is valid (i.e. exactly 9 rows exist with no conflicts).

| Column | Type | Notes |
|---|---|---|
| lineup_id | UUID | FK to lineups.id |
| batting_position | integer | 1–9 |
| player_id | UUID | FK to players.id |
| field_position | field_position | Eligible position for this player; P only allowed for two-way SP |

Primary key: (lineup_id, batting_position)

**Two-way player note:** If the SP is batting, a row exists for him in this table with field_position = P. If a DH is used instead, no such row exists for the SP, and a batter occupies one slot with field_position = DH. These two states are mutually exclusive.

## 4. Player Stats

Two stat snapshots are captured per player per matchup, both by the data pipeline:

- **pre_lock**: season stats up to the lineup lock date. Used by the AI manager for in-game decisions. Captured at the batting order lock time.
- **post_lock**: stats from the period between lineup lock and sim run. Used to estimate outcome probabilities in the sim. Captured just before the sim fires.

Batters and pitchers have separate stat tables due to their distinct stat sets. Two-way players have rows in both tables.

## Data Ownership Summary

| Table | Populated by |
|---|---|
| profiles | User action (registration) |
| leagues, teams | User action (commissioner creates league) |
| players, player_positions | Data pipeline |
| roster_players | User action (draft, waiver wire) |
| matchups | Platform (schedule generation at season start) |
| lineups, lineup_batting_order | Platform (defaults at matchup creation); user action (edits) |
| batter_matchup_stats, pitcher_matchup_stats | Data pipeline (pre_lock at batting order deadline; post_lock just before sim) |
| sim_events, sim_batter_stats, sim_pitcher_stats, sim_line_score | Sim engine |
| matchups.sim_status | Sim engine (updates to sim_pending, then sim_complete) |
